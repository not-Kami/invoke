## Refactorisation de la page /games

### Objectif
Remplacer les données mockées par de vraies données de la base de données via l'API

### Problèmes identifiés
- **Conflit de types** : Le composant `GameCard` existant attend un type `Game` avec propriété `images` (pluriel), mais l'API retourne un type `Game` avec propriété `image` (singulier)
- **Données statiques** : Utilisation de `mockGames` au lieu de l'API `publicAPI.getGames()`
- **Gestion d'erreur** : Pas de gestion des erreurs API ou des états de chargement

### Solutions implémentées

#### 1. Création d'un composant GameCard spécifique
- **Composant inline** : `SimpleGameCard` créé spécifiquement pour la page games
- **Type compatible** : Utilise le type `Game` de l'API (`client/src/lib/api`)
- **Design cohérent** : Même style visuel que le composant original mais adapté à la structure de données de l'API

#### 2. Intégration de l'API
- **Endpoint** : `publicAPI.getGames()` pour récupérer tous les jeux
- **Gestion d'état** : Ajout de `loading` et `error` states
- **Gestion d'erreur** : Affichage des erreurs avec bouton de retry
- **Fallback** : Image par défaut (🎲) si pas d'image disponible

#### 3. Filtres dynamiques
- **Génération automatique** : Les listes de genres et systèmes sont générées dynamiquement depuis les données de l'API
- **Tri alphabétique** : Genres et systèmes triés par ordre alphabétique
- **Filtrage en temps réel** : Recherche, genre et système fonctionnent avec les vraies données

### Structure finale
```typescript
// Composant SimpleGameCard inline
function SimpleGameCard({ game, onClick, className }) {
  // Gère game.image (API) au lieu de game.images (types)
  // Design identique au composant original
}

// États de gestion
const [games, setGames] = useState<Game[]>([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState<string | null>(null);

// Appel API
useEffect(() => {
  const loadGames = async () => {
    try {
      setLoading(true);
      const response = await publicAPI.getGames();
      if (response.success && response.data) {
        setGames(response.data);
      } else {
        setError(response.error || 'Erreur lors du chargement des jeux');
      }
    } catch (err) {
      setError('Erreur de connexion au serveur');
    } finally {
      setLoading(false);
    }
  };
  loadGames();
}, []);
```

### Avantages de cette approche
- **Données réelles** : Plus de données mockées, tous les jeux de la DB sont affichés
- **Filtres dynamiques** : Les filtres s'adaptent automatiquement au contenu de la base
- **Gestion d'erreur** : États de chargement et d'erreur bien gérés
- **Performance** : Un seul appel API au chargement de la page
- **Maintenance** : Plus besoin de maintenir des données mockées

### Prochaines étapes possibles
- **Optimisation des filtres** : Ajout d'un enum hardcodé pour les systèmes si la requête devient trop complexe
- **Pagination** : Ajout de pagination si le nombre de jeux devient important
- **Cache** : Mise en cache des données pour éviter les appels API répétés
- **Recherche avancée** : Implémentation de recherche côté serveur pour de meilleures performances
